# Agent HQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local-only Goldenrod City where a Claude character picks up tickets from an in-town board, works them via `claude -p`, and writes results back to SQLite and the Obsidian vault, all visible live in town.

**Architecture:** One zero-dependency Node server (`node:http`, `node:sqlite`, SSE) wraps four small modules (store, runner, activity, vault). The browser runs the town engine copied from the portfolio, with an adapted `main.js` that renders the board as Game Boy pages and drives a Claude NPC from SSE agent state.

**Tech Stack:** Node 26 (ES modules, `node:sqlite`, `node:test`), vanilla JS canvas, Claude Code CLI 2.1.x.

**Spec:** `docs/superpowers/specs/2026-10-30-agent-hq-design.md`

## Global Constraints

- Repo is `~/agent-hq`. Never modify `~/FaiGiJoon.github.io`; only copy from it.
- No npm dependencies. `package.json` exists only for `"type": "module"` and the `test` script.
- Server binds `127.0.0.1` only; reject any `Host` header other than `127.0.0.1:<port>` / `localhost:<port>` with 403.
- Defaults: `PORT=4317`, `VAULT=~/Documents/Obsidian Vault`, `CLAUDE_BIN=claude`, `TICKET_TIMEOUT_MS=600000`, `MAX_BUDGET_USD=1`.
- Statuses: `open | queued | working | done | failed`. Event kinds: `created | assigned | started | step | done | failed | reset`.
- Step labels: `THINK`, `READ`, `WEB`, `WRITE`, `SEARCH`.
- Claude never gets Bash and never writes to the vault; the server writes the vault note.
- Vault notes: `00-inbox/agent-hq-<id>-<slug>.md`, YAML frontmatter, no emojis, never overwrite.
- Text shown on the canvas only uses characters the Crystal font has (the copied `Font.has`); strip or replace others.
- Tests: `node --test test/` must pass at the end of every task.

## Review Focus

1. Ticket title/body with characters the GB font lacks (emoji, accents, `<`, quotes): canvas must not break; text is sanitized for display, stored raw. Test in Task 7 (`displayText`).
2. Claude CLI prints non-JSON lines or a partial last line on stdout: runner skips them and still finishes. Test in Task 5 (`fake-claude` mode `noise`).
3. Assigning a ticket twice or assigning while another runs: second call is a no-op 409, the queue never runs two at once. Test in Task 2 (`assign` on non-open) and Task 5 (`queue runs one at a time`).
4. Title that slugs to empty (e.g. only symbols) or a very long title: vault filename is still valid (`agent-hq-<id>-ticket.md`, slug max 40 chars). Test in Task 4.
5. Browser opened on `localhost` vs `127.0.0.1`, or a page served from another origin calling the API: both local hosts work, foreign `Host` gets 403. Test in Task 6.

### Task 2: Ticket store

**Files:**
- Create: `hq/store.js`
- Test: `test/store.test.mjs`

**Interfaces:**
- Produces: `class Store` — `constructor(path = ':memory:')` (creates tables), `create({ title, body }) → ticket`, `get(id) → ticket | null`, `list() → ticket[]` (newest first), `events(id) → event[]` (oldest first), `assign(id) → ticket` (only from `open`; sets `assignee='claude'`, `status='queued'`), `retry(id) → ticket` (only from `failed` → `queued`), `setStatus(id, status, fields = {}) → ticket` (fields: `output`, `note_path`), `addEvent(id, kind, text = '') → event`, `nextQueued() → ticket | null` (oldest queued), `resetWorking() → ticket[]` (working → queued, adds `reset` event each). `onChange(fn)` registers a listener called as `fn({ type: 'ticket', ticket })` or `fn({ type: 'event', event })` on every change.
- Ticket shape: `{ id, title, body, assignee, status, output, note_path, created_at, updated_at }` (ISO strings). Event shape: `{ id, ticket_id, at, kind, text }`.
- Errors: `class StoreError extends Error` with `.status` (400 bad input, 404 missing, 409 wrong state).

  - `retry` only from `failed`; otherwise 409. `get(999)` is null; `assign(999)` → 404.
  - `nextQueued` returns the oldest queued ticket.
  - `resetWorking` moves working → queued and adds a `reset` event.

**Interfaces:**
- Consumes: `Store` (Task 2), `stepsFrom`, `describe` (Task 3), `writeNote` (Task 4), `config` shape (Task 1).
- Produces: `claudeArgs(ticket, { vault, maxBudgetUsd }) → string[]` — exactly:
  `['-p', prompt(ticket, vault), '--output-format', 'stream-json', '--verbose', '--allowedTools', 'Read', 'Glob', 'Grep', 'WebSearch', 'WebFetch', 'Write', 'Edit', '--disallowedTools', 'Bash', 'Write(<vault>/**)', 'Edit(<vault>/**)', '--add-dir', vault, '--permission-mode', 'dontAsk', '--max-budget-usd', String(maxBudgetUsd)]`.
  `prompt` states the title and body, that the vault at `<vault>` is read-only reference, that files may only be written in the current folder, and to end with the final answer in Markdown.
- Produces: `class Runner` — `constructor({ store, config, writeNote = vault.writeNote })`, `agent → { status: 'idle'|'working', ticket: id|null, step: {label, detail}|null }`, `onAgent(fn)` (called with `agent` on every change), `kick()` (start the next queued ticket if idle; safe to call any time), `async idle()` (resolves when nothing is running and nothing is queued; for tests).
- Behaviour (spec "Runner" section): create `workDir/<id>/`, `setStatus(working)` + `started` event, spawn `claudeBin` with `claudeArgs`, `cwd` the work dir, stdin ignored. Split stdout on `\n`, `JSON.parse` each line in try/catch (skip non-JSON), each step → `step` event `"<label> <detail>"` and agent update. `result` message with `is_error !== true` and exit 0 → `done` with `output = result.result`, then `writeNote`; on `writeNote` failure add a `step` event `"Could not write vault note: <message>"` and still `done`. Else → `failed` with `"exit <code>: <last 5 stderr lines>"` (or `"timed out after <n> min"` after `SIGKILL` on timeout, or the spawn error message). After finishing, `kick()` again.
